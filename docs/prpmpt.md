You are an experienced UI/UX designer and technical marketing artist.

Your task is to create a professional GitHub README hero image for an open-source software project.

The goal is NOT to create AI-looking promotional art.

Instead, create something that feels like it was designed by a senior product designer at companies like Linear, Vercel, Stripe, Raycast, Notion, Docker, Supabase, or JetBrains.

------------------------------------------------
DESIGN PRINCIPLES
------------------------------------------------

The image should immediately communicate:

• what the software does
• who it is for
• how it feels to use

without relying on large paragraphs.

Avoid fantasy artwork.

Avoid generic AI glowing effects.

Avoid random neon lines.

Avoid fake holograms.

Avoid cyberpunk aesthetics unless the project itself requires them.

Avoid fake code floating in space.

Avoid giant meaningless icons.

Avoid stock-photo style illustrations.

Everything shown must have purpose.

------------------------------------------------
VISUAL STYLE
------------------------------------------------

Use a clean product showcase style.

Imagine this image being used on:

- GitHub README
- Product Hunt
- Personal Portfolio
- Developer Blog
- Documentation Landing Page

Prefer:

soft lighting

subtle shadows

realistic depth

clean composition

minimal decoration

modern typography

consistent spacing

professional color palette

The image should look handcrafted instead of AI generated.

------------------------------------------------
LAYOUT
------------------------------------------------

Build the composition around the actual product.

Possible layouts:

• desktop monitor
• laptop
• phone mockup
• terminal window
• browser window
• dashboard
• editor
• code window
• architecture diagram
• API flow
• CLI window

depending on what best represents the software.

Use realistic device frames only if appropriate.

Show multiple screens only when they help explain the product.

Never overload the composition.

Leave generous whitespace.

------------------------------------------------
FOCUS
------------------------------------------------

The software itself must be the hero.

Everything else only supports it.

Instead of decorating the image,
tell the product story visually.

Examples:

Automation Tool
→ keyboard shortcuts
→ workflow arrows
→ before/after behavior

Finance App
→ dashboard
→ charts
→ transactions
→ statistics

Browser Tool
→ browser window
→ floating controls
→ popup authentication
→ refresh indicator

CLI Tool
→ terminal output
→ command examples
→ execution result

API
→ request
→ processing
→ response

Backend
→ architecture
→ services
→ database
→ deployment

Library
→ code snippet
→ output
→ integration example

AI Project
→ prompt
→ inference
→ generated result

------------------------------------------------
COLOR
------------------------------------------------

Base the palette on the application's branding if available.

Otherwise use:

neutral background

white

light gray

dark graphite

accent color from the project

Avoid rainbow gradients.

Avoid excessive glow.

------------------------------------------------
TYPOGRAPHY
------------------------------------------------

Minimal.

Only include:

project name

short tagline

2–5 feature labels if necessary

Avoid marketing buzzwords everywhere.

------------------------------------------------
QUALITY
------------------------------------------------

The image should look like it belongs on:

apple.com

stripe.com

linear.app

vercel.com

notion.so

supabase.com

instead of looking like a typical AI poster.

------------------------------------------------
OUTPUT
------------------------------------------------

Produce a high-resolution GitHub README hero banner.

Aspect ratio:
16:9

Resolution:
At least 1920 × 1080.

The result should feel like a real software landing page hero section rather than AI-generated concept art.
